resolution: NOT A BUG -- the premise is factually wrong, and the design already prevents the drift the ticket describes.

There is no checked-in copy of STATE.md to drift. Verified three ways: it is in .gitignore (line 24), 'git ls-files STATE.md' is empty, and 'git log --all -- STATE.md' is empty, so it has NEVER been tracked. It does not currently exist on disk either -- nothing in the repo creates it unless a human passes 'state --write'.

The gitignore is deliberate and the rationale is written down. docs/superpowers/specs/2026-08-29-bets-raise-lane-design.md, explaining why BETS.md follows the same rule: 'The file is gitignored for the same reason the enforcing-surfaces spec gitignores STATE.md: a tracked generated file drifts the moment someone edits it.' That is precisely the failure this ticket is worried about; the answer was to never track the file.

So the ticket's own second option -- 'whether the file should go' -- is already the shipped design, in the only sense that matters: the file is not part of the repo. What ships is the COMMAND. 'python -m tools.cli state' renders the orientation surface live from the DB every time it is run, which is what CLAUDE.md tells every session to orient with and what cannot go stale by construction. '--write' is an optional convenience for a human who wants it in a file, documented in README.md as exactly that.

Nothing reads STATE.md programmatically -- the only code references are tools/state.py::write_state (the writer), tools/cli.py (the --write flag), and tests. So making the floor write it would add a build step producing an artifact with no consumer, and tracking it would create the drift the spec avoided on purpose.

No code change. Closed so nobody re-investigates it.
